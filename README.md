# MOTIVA API — Sprint 4

**Migração de JDBC puro para Spring Boot + Spring Data JPA + API REST**

## 1. O que foi implementado

A aplicação migra o protótipo console da Sprint 3 para uma API REST organizada em camadas:

```text
br.com.motiva
├── MotivaApplication.java
├── model/       # Entidades JPA mapeadas às tabelas Oracle
├── repository/  # Interfaces JpaRepository e derived queries
├── service/     # Regras de negócio, validações e motor de prioridade
├── controller/  # Endpoints REST / JSON
├── dto/         # Contratos de entrada e saída da API
└── exception/   # Tratamento global de erros
```

Recursos implementados: CRUD de trechos, equipes e intervenções; geração persistida do relatório; consulta ao histórico e por período; DTOs; Bean Validation; tratamento global de erros; testes MockMvc com banco H2 isolado no perfil de testes; consultas derivadas do Spring Data; e scripts para registrar requisições reais.

### Mapeamento do banco da Sprint 3

| Entidade JPA | Tabela Oracle | Colunas mapeadas |
|---|---|---|
| `TrechoRodovia` | `TRECHO_RODOVIA` | `ID`, `KM`, `CRESCIMENTO_VEGETACAO`, `TIPO_TRECHO` |
| `EquipeManutencao` | `EQUIPE_MANUTENCAO` | `ID`, `NOME_EQUIPE`, `RESPONSAVEL` |
| `IntervencaoOperacionalEntity` | `INTERVENCAO_OPERACIONAL` | `ID`, `TIPO`, `DESCRICAO` |
| `RelatorioPrioridade` | `RELATORIO_PRIORIDADE` | `ID`, `DATA_GERACAO`, `QT_URGENTE`, `QT_CRITICO`, `QT_ATENCAO`, `QT_NORMAL`, `RESUMO` |

**Scripts de referência:** `sql/sprint3-criacao-referencia.sql` e `sql/sprint3-dados-referencia.sql` são cópias dos scripts recebidos. Use-os apenas para entender/recriar um ambiente vazio; não os execute se as tabelas e os dados da equipe já existirem.

**Observação sobre IDs:** o script da Sprint 3 usa `GENERATED BY DEFAULT AS IDENTITY`, não sequences nomeadas. Por isso, a entrega inclui `sql/sprint4-sequences.sql`, migração de execução única que cria sequences começando em `MAX(ID) + 1`; a estrutura das tabelas existentes não é recriada. Execute o script no schema Oracle da equipe antes de iniciar a API. O uso de `allocationSize=1` mantém o passo das sequences alinhado ao banco.

## 2. Requisitos

- JDK 17 ou superior.
- Maven 3.6.3 ou superior.
- Acesso à base Oracle FIAP e às tabelas criadas na Sprint 3.
- Credenciais válidas da conta Oracle.

O projeto usa Spring Boot **4.1.1**, Java 17, `spring-boot-starter-web`, `spring-boot-starter-data-jpa`, Bean Validation e o driver `com.oracle.database.jdbc:ojdbc17` via Maven. O Spring Boot 4.1.1 requer Java 17 ou superior e Maven 3.6.3 ou superior, conforme a documentação oficial: https://docs.spring.io/spring-boot/system-requirements.html

## 3. Preparar o Oracle e executar

1. Abra o SQL Developer ou a ferramenta utilizada pela equipe e conecte ao mesmo schema Oracle da Sprint 3.
2. Execute **uma vez** `sql/sprint4-sequences.sql`. Se as sequences já existirem, não rode novamente sem verificar o estado do schema.
3. Configure as variáveis de ambiente para não salvar senhas no código nem no Git.

PowerShell:

```powershell
$env:ORACLE_URL = "jdbc:oracle:thin:@oracle.fiap.com.br:1521:ORCL"
$env:ORACLE_USER = "SEU_RM"
$env:ORACLE_PASSWORD = "SUA_SENHA"
mvn spring-boot:run
```

Bash:

```bash
export ORACLE_URL='jdbc:oracle:thin:@oracle.fiap.com.br:1521:ORCL'
export ORACLE_USER='SEU_RM'
export ORACLE_PASSWORD='SUA_SENHA'
mvn spring-boot:run
```

Substitua os exemplos pelas credenciais do próprio aluno. Não grave os valores reais em `application.properties`, `.env.example`, scripts ou no repositório. A propriedade `spring.jpa.hibernate.ddl-auto=validate` faz o Hibernate validar o mapeamento; ela **não** cria nem modifica as tabelas existentes.

A API estará disponível em `http://localhost:8080`. Para rodar os testes sem Oracle e guardar a saída real em arquivo (PowerShell):

```powershell
.\scripts\executar-testes.ps1
```

Ou execute diretamente `mvn test` e confira a saída Surefire em `target/surefire-reports/`. A suíte usa H2 em memória e não modifica o Oracle FIAP.

Documentação adicional: [`RELATORIO_ACADEMICO.md`](RELATORIO_ACADEMICO.md) e [`RELATORIO_TESTES.md`](RELATORIO_TESTES.md). O segundo documento registra o estado real da validação e explica como gerar logs de execução.

## 4. Endpoints REST

Todos os recursos usam JSON (`Content-Type: application/json`). Campos e filtros são sensíveis aos limites e tipos descritos nas entidades/DTOs.

| Método | Endpoint | Descrição | Resposta esperada |
|---|---|---|---|
| GET | `/api/trechos` | Lista trechos; filtro opcional `?tipo=umido` | `200 OK` |
| GET | `/api/trechos/{id}` | Busca trecho por ID | `200 OK` / `404 Not Found` |
| GET | `/api/trechos/vegetacao?minimo=50` | Vegetação maior ou igual ao mínimo | `200 OK` / `400 Bad Request` |
| POST | `/api/trechos` | Cria trecho | `201 Created` + corpo e `Location` |
| PUT | `/api/trechos/{id}` | Atualiza trecho | `200 OK` / `404 Not Found` |
| DELETE | `/api/trechos/{id}` | Exclui trecho | `204 No Content` / `404 Not Found` |
| GET | `/api/equipes` | Lista equipes; filtro opcional `?nome=Norte` | `200 OK` |
| GET | `/api/equipes/{id}` | Busca equipe por ID | `200 OK` / `404 Not Found` |
| POST | `/api/equipes` | Cria equipe | `201 Created` |
| PUT | `/api/equipes/{id}` | Atualiza equipe | `200 OK` / `404 Not Found` |
| DELETE | `/api/equipes/{id}` | Exclui equipe | `204 No Content` / `404 Not Found` |
| GET | `/api/intervencoes` | Lista intervenções; filtro opcional `?tipo=roçada` | `200 OK` |
| GET | `/api/intervencoes/{id}` | Busca intervenção por ID | `200 OK` / `404 Not Found` |
| POST | `/api/intervencoes` | Cria intervenção | `201 Created` |
| PUT | `/api/intervencoes/{id}` | Atualiza intervenção | `200 OK` / `404 Not Found` |
| DELETE | `/api/intervencoes/{id}` | Exclui intervenção | `204 No Content` / `404 Not Found` |
| POST | `/api/relatorios` | Gera relatório dos trechos atuais e persiste no histórico | `201 Created` |
| GET | `/api/relatorios` | Lista o histórico mais recente primeiro | `200 OK` |
| GET | `/api/relatorios/{id}` | Busca relatório por ID | `200 OK` / `404 Not Found` |
| GET | `/api/relatorios/periodo?inicio=...&fim=...` | Busca relatórios entre duas datas | `200 OK` / `400 Bad Request` |

Para o período, use `LocalDateTime` em ISO 8601, sem fuso, por exemplo `2026-01-01T00:00:00`.

## 5. Exemplos cURL

### Criar trecho

```bash
curl -i -X POST http://localhost:8080/api/trechos \
  -H 'Content-Type: application/json' \
  -d '{"km":10,"crescimentoVegetacao":85,"tipoTrecho":"umido"}'
```

A API retorna `201 Created`, o objeto com `id` e um cabeçalho `Location` para o recurso criado.

### Listar e filtrar trechos

```bash
curl -i http://localhost:8080/api/trechos
curl -i 'http://localhost:8080/api/trechos?tipo=umido'
curl -i 'http://localhost:8080/api/trechos/vegetacao?minimo=50'
```

### Atualizar e excluir trecho

```bash
curl -i -X PUT http://localhost:8080/api/trechos/1 \
  -H 'Content-Type: application/json' \
  -d '{"km":10,"crescimentoVegetacao":40,"tipoTrecho":"umido"}'

curl -i -X DELETE http://localhost:8080/api/trechos/1
```

### Criar equipe e intervenção

```bash
curl -i -X POST http://localhost:8080/api/equipes \
  -H 'Content-Type: application/json' \
  -d '{"nomeEquipe":"Equipe Norte","responsavel":"Carlos Silva"}'

curl -i -X POST http://localhost:8080/api/intervencoes \
  -H 'Content-Type: application/json' \
  -d '{"tipo":"Roçada Mecanizada","descricao":"Roçada em trecho crítico"}'
```

### Gerar e consultar relatório

```bash
curl -i -X POST http://localhost:8080/api/relatorios
curl -i http://localhost:8080/api/relatorios
curl -i 'http://localhost:8080/api/relatorios/periodo?inicio=2026-01-01T00%3A00%3A00&fim=2026-12-31T23%3A59%3A59'
```

A geração de relatório usa os trechos persistidos no momento da chamada, classifica cada um, monta o resumo e grava contagens e texto na tabela `RELATORIO_PRIORIDADE`.

## 6. Motor de prioridade

Foram preservados os limiares do `GeradorRelatorio` da Sprint 3:

| Crescimento da vegetação | Classificação | Intervenção sugerida |
|---|---|---|
| `>= 80` | URGENTE | Roçada Mecanizada |
| `>= 50` e `< 80` | CRÍTICO | Roçada Manual |
| `>= 30` e `< 50` | ATENÇÃO | Monitoramento |
| `< 30` | NORMAL | Sem necessidade imediata |

A classificação fica em `GeradorRelatorioService`, não nos Controllers. Os campos `qtUrgente`, `qtCritico`, `qtAtencao` e `qtNormal` são persistidos no histórico.

## 7. Queries derivadas

Os repositórios incluem métodos derivados, por exemplo:

- `TrechoRodoviaRepository.findByCrescimentoVegetacaoGreaterThanEqual(BigDecimal minimo)`
- `TrechoRodoviaRepository.findByTipoTrechoIgnoreCase(String tipoTrecho)`
- `EquipeManutencaoRepository.findByNomeEquipeContainingIgnoreCase(String nomeEquipe)`
- `IntervencaoOperacionalRepository.findByTipoContainingIgnoreCase(String tipo)`
- `RelatorioPrioridadeRepository.findByDataGeracaoBetweenOrderByDataGeracaoDesc(inicio, fim)`

Não há SQL manual em Service ou Controller, nem uso de `Connection`, `PreparedStatement` ou `ResultSet`. O Spring Data JPA interpreta os nomes dos métodos e gera a consulta correspondente em tempo de execução.

## 9. Perguntas de reflexão

**1. Por que o `Repository` é uma interface, quem escreve a implementação e quando?**

A interface declara operações de persistência e queries derivadas sem conter o código de acesso ao banco. Ao iniciar a aplicação, o Spring Data detecta a interface e cria um proxy que implementa os métodos declarados; a consulta é preparada/gerada a partir do método e executada quando ele é chamado. Isso evita repetir código de CRUD em cada DAO.

**2. O pattern DAO morreu na migração?**

Não. A responsabilidade de acesso aos dados continua separada das regras de negócio, mas o Spring Data Repository passa a cumprir esse papel. O código deixa de implementar manualmente cada método JDBC e passa a declarar uma interface `JpaRepository`.

**3. Por que validar `crescimentoVegetacao >= 0` no Service e não só no Controller?**

A regra pertence ao domínio e deve valer independentemente de quem chamou a operação: API REST, teste automatizado ou outro serviço. O Controller valida o contrato HTTP com `@Valid`, enquanto o Service repete as invariantes importantes para proteger a regra de negócio mesmo se for reutilizado por outra entrada. Assim, não se depende exclusivamente de uma camada de interface.

**4. Onde está o SQL do `findByTipo...()` e quem o gerou?**

O SQL não é escrito manualmente no projeto. O método é declarado na interface do Repository; durante a criação do proxy do Spring Data JPA, o framework interpreta o nome e prepara uma consulta compatível com o mapeamento da entidade e o dialeto do banco. O Hibernate transforma a consulta em SQL para o Oracle na execução.

## 10. Git recomendado

Abaixo está um exemplo de como separar o projeto em commits por camada. Faça os commits no momento em que cada parte for preparada; não altere autores ou datas para aparentar um histórico anterior.

```bash
git init
git add .gitignore pom.xml .env.example src/main/java/br/com/motiva/MotivaApplication.java src/main/resources/application.properties
git commit -m "chore: cria estrutura Spring Boot da Sprint 4"

git add src/main/java/br/com/motiva/model src/main/java/br/com/motiva/repository
git commit -m "feat: mapeia entidades JPA e repositories"

git add src/main/java/br/com/motiva/service src/main/java/br/com/motiva/dto
git commit -m "feat: implementa regras de negócio e DTOs"

git add src/main/java/br/com/motiva/controller src/main/java/br/com/motiva/exception
git commit -m "feat: expõe CRUD REST e tratamento global de erros"

git add src/test sql scripts postman evidencias README.md RELATORIO_ACADEMICO.md RELATORIO_ACADEMICO.docx RELATORIO_TESTES.md
git commit -m "test: documenta e prepara validação dos endpoints"
```

Depois, crie o repositório remoto da equipe e publique com `git remote add origin URL_DO_REPOSITORIO` e `git push -u origin main`. Confirme que o histórico é real e que nenhum arquivo inclui credenciais.
